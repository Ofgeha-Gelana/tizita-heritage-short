# Costs and measurements

**Actual spend: $0.** Every model ran on a free tier with no payment card. The list-price columns below show what the same calls would cost on paid tiers, so the numbers can be compared and budgeted. List prices are hand-entered estimates in `pipeline/common.py:LIST_PRICE` (Gemini paid tier, Cloudflare at $0.011 per 1k neurons beyond the free 10k/day, and a T4 at about $0.35/GPU-hour on a public cloud). Check them against each provider's pricing page before relying on them.

All numbers come from `runs.jsonl` (one line per model call) through `make costs`, unless marked *estimate*.

**Video is about 90% of the cost and time.** Everything else together costs less than a cent per shot. That is why the pipeline caches per shot: changing one shot regenerates one clip (about 13 GPU-minutes), not ten.

A re-run with no storyboard change makes **0 model calls**: run `20261126T095003Z`, `[run] done in 17s; 0 model call(s) logged`; its only two runs.jsonl lines are the local `ffmpeg` exports. Only the local FFmpeg assembly runs again, and the exports come out byte-identical (no git diff on `outputs/final/*.mp4`).

## Free-tier limits as found

| Provider | What the brief said | What we actually hit (date) |
|---|---|---|
| Gemini TTS | free tier | **10 requests/day per TTS model, 3 requests/min** (2026-11-25, HTTP 429 with a per-day quota id). Each model has its own daily bucket, so the pipeline walks a fallback chain and remembers which models are spent until the Pacific-midnight reset (11:00 EAT). |
| Gemini text | free tier | No quota hit, but `gemini-3.8-flash` returned **503 "high demand"** on both days (F3). Translation falls back to `gemini-3.5-flash-lite`. |
| Cloudflare Workers AI | ~10k neurons/day | No limit hit at 33 images/day across two models. `flux-1-schnell` no longer accepts `seed` (F6). |
| Kaggle GPU | ~30 GPU h/week, T4 ×2 | **At most 2 concurrent batch GPU sessions** (`Maximum batch GPU session count of 2 reached`, F7). About 3.5 of the ~30 weekly hours used. Kernel logs are only readable after a run finishes. Listing outputs that include a venv gets **rate-limited (429)** (F10). |

## Notes on measurement

- `latency_ms` is the wall time of the HTTP call, or of the job inside the Kaggle kernel. It does not include Kaggle queue time, model download or model loading, which show up in the kernel logs in `outputs/logs/`.
- `gpu_s` is the job's wall time on its GPU. With two workers in parallel, total GPU-minutes (137.8) are about twice the wall time (~66 min).
- The table counts calls, not quota consumed. A 429 is a logged call that used no quota but cost time.
